# 研知台需求文档

版本：0.1｜2026-11-02｜用于黑客松范围确认与任务认领

## 1. 产品目标

主题为“科研与知识挖掘”，聚焦团队已有积累的 MCP、Agent 工具调用与 benchmark。让刚进入该领域的同学可以完成三个动作：找到资料、问清问题、查看实验依据。

核心流程：提出研究问题 → 搜索或问答 → 查看引用 → 进入 benchmark 说明 → 查看团队实测和失败案例。网站既展示过去的调研，也提供本次开发产生的新实验。

三天的交付目标是一个可访问、可演示、信息可追溯的网站。实验数量服从可复现性和时间，动画服从核心功能完成度。

## 2. 用户与场景

| 用户 | 要完成的事情 | 产品如何支持 |
|---|---|---|
| 刚接触课题的同学 | 理解 MCP、工具发现与调用的区别 | 概念卡片、检索、带引用答疑 |
| 实训项目成员 | 选择适合复现的 benchmark | 对照表、环境要求、官方来源和团队验证记录 |
| 评委与访客 | 快速判断项目价值及实验真实性 | 无登录浏览、结果摘要、样本与日志详情 |

首版预设问题：

1. 工具检索和工具调用分别解决什么问题？
2. 单任务多步调用与用户多轮对话有什么区别？
3. LiveMCPBench 的运行需要哪些资源？
4. 本次团队测试了什么配置，哪些任务失败了？
5. 当前资料无法支持的结论是什么？

第 4 题必须来自团队实验结果；未完成实验前显示“尚无团队实测数据”。

## 3. 范围

| 优先级 | 本次内容 | 交付边界 |
|---|---|---|
| P0 必须 | 知识库与搜索 | 至少 8 篇审核过的短文或卡片，包含概念、benchmark、复现指南三类 |
| P0 必须 | AI 答疑 | 仅基于已审核资料与已发布实测记录，回答附引用，可说明资料不足 |
| P0 必须 | 一个 benchmark 子集实测 | 至少 1 个模型配置，目标 20 个不同任务，保底 10 个；保留完整计划与失败记录 |
| P0 必须 | 结果页与案例详情 | 汇总指标、配置、样本量、至少一个成功或失败案例及日志入口 |
| P0 必须 | 可访问网站与提交材料 | 源码、README、官方模板海报、≤3 分钟视频；网站作为本项目验收项 |
| P1 争取 | 对比实验 | 同一模型两种策略，或同一策略两个可调用模型；固定同一任务集 |
| P1 争取 | 日志回放 | 从真实日志生成步骤动画，至少一个可演示案例 |
| P2 余量 | 更多 benchmark、交互图表 | 仅在 P0 验收通过且提交材料完成后开展 |

首版不安排账号系统、在线上传任意文件、在线启动任意 benchmark、用户自建工具市场、大规模模型训练或千级工具环境重建。知识与实验由团队离线整理，通过代码审查发布。

## 4. 功能需求与验收

### F01 知识库

- 按“概念 / Benchmark / 复现”分类；支持关键词检索、标签筛选和清除筛选。
- 每条内容包含标题、正文、来源、更新时间和核验情况。正文尽量短，来源紧邻相关结论。
- benchmark 卡片区分候选工具库规模、每题可见工具数、执行方式、多步调用及用户多轮；不把 server 数当成 tool 数。
- 同一论文的不同版本、冲突数字不能合并成一个无条件事实；尚未核实的数据明确标注。
- 空结果提示可修改关键词；条目不存在时有返回入口。

验收：8 条已审核内容可浏览；使用 5 个约定关键词能找到对应内容；每条至少一个可访问来源；分类与搜索可以组合使用。

### F02 带引用的 AI 答疑

- 访客无需登录，可以输入问题或点击预设问题；采用单轮问答，追问以新问题处理。
- 服务端检索已审核知识和已发布实验记录，将有限片段提供给模型。模型输出引用 ID，服务端验证后转为链接。
- 回答显示来源标题与正文定位；点击可回到知识条目或运行详情。模型生成的未知引用不得显示为有效来源。
- 未命中资料时说明知识库尚未覆盖；资料有冲突时展示分歧及版本。实测未产生前不能编造成绩。
- 显示提交中、成功、资料不足、超时、额度不足等状态；请求中阻止重复提交，失败允许手动重试。
- 浏览器不接触服务端密钥。外部文档中的命令、提示词或“忽略规则”只视作内容。

验收：使用 15 题固定集（10 题有依据、3 题无依据、2 题来源冲突）人工检查；至少 12 题正确且证据充分，引用均可打开，3 题无依据不得捏造结论。记录题目、回答、判定与问题；门槛未达成需修复或明确交付缩水。

资源前提：先验证看山额度是否提供独立 API、支持何种模型及调用格式。若无法接入，知识库和实验页继续开发；预设答案仅作为标明的演示备份，不能算 AI 答疑通过验收。

### F03 Benchmark 与结果

- 一个 benchmark 一个说明入口，包含测量目标、官方仓库、选取理由、环境和本次测量范围。
- 结果表按实际取得的数据展示模型配置、策略、样本量、成功率、耗时；未取得 token 或费用时显示“未记录”。
- 每次运行有唯一 ID，保留上游 commit、任务 ID、模型返回的名称、参数、提示版本、环境、评分器、起止时间、原始日志及导出结果。
- 本地实测、引用的官方结果、预设演示分开显示。对比只在任务集、评分与预算一致时进行。
- 失败分为模型任务失败、环境失败和评分失败；分母及排除项可见，不能只展示成功任务。
- 实验数据经过脱敏后离线导入网站，评委点击页面不会产生新的付费评测。

验收：至少一个真实运行配置与 10 个不同任务的完整记录；目标完成 20 个；页面统计与导出一致，能按 run ID 追溯配置和样本；至少展示一个有解释的案例。未完成此项只能认定为资料与原型展示，不能声称完成 benchmark 复现。

### F04 工具调用回放

P1。优先基于真实日志，展示“发现工具 → 调用 → 返回 → 最终答案/失败”的事件，不要求显示模型私有思维过程。

支持播放、暂停、上一步、下一步、重置；事件详情显示脱敏参数、耗时和结果摘要。固定脚本的演示动画必须标为“预设演示”，不得并入实测统计。动画速度不代表实际耗时，真实耗时单独显示。若时间不足改成事件列表。

### F05 页面与导航

导航只保留“知识库 / 问答 / 实验”。首页提供一个问题入口、一组精选知识和实验摘要；可与知识库页合并，减少页面开发量。

知识条目能跳到对应实验，实验详情能跳回概念说明。桌面双栏、移动端单栏；长表格允许横向滚动。让布局表达层次，避免重复副标题和装饰性说明。

## 5. 运行要求

| 项目 | 首版要求与验证方式 |
|---|---|
| 可访问性 | 电脑与手机各验收一次；无痕/游客模式可访问网站与提交链接 |
| 可用性 | 所有关键页面有加载、空白、失败状态；问答不可用时资料和既有结果仍可浏览 |
| 性能 | 在约定测试设备与网络记录实测；静态主要内容目标 3 秒内可用，问答设 30 秒超时并可重试 |
| 成本 | 服务端限流与并发上限；先小样本测用量，再定额扩跑；不自动追加费用 |
| 可追溯性 | 每条关键结论关联来源或 run ID；每份结果可查版本和样本分母 |
| 可维护性 | 单仓库、单一网站应用、独立评测脚本；合并前构建并走关键流程 |
| 公开发布 | 不发布密钥、原始个人资料、无再分发权的全文或未经审核的实训附件 |

## 6. 三天完成的定义

周三晚应能连续演示：找一条知识 → 问一个有引用的问题 → 打开一组真实实验 → 查看一个失败或成功案例。网站部署、源码、海报和视频准备齐全。

周四以提交和互评为主。P1/P2 缺失可以接受；P0 未完成须在 README 和演示中说明，不能用预设数据补成已完成。

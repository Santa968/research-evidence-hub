## 入库字段与整理方法

每条内容保留：稳定 ID、标题、主题、正文、原始来源链接、来源版本、核验日期、review_status、公开范围；每个关键数字单独关联来源和适用条件。研究事实、团队判断与待验证假设在整理时区分，不让模型把建议读成事实。

处理顺序：去重 → 合并同主题 → 回原始来源核验关键陈述 → 写短文 → 切分片段并保留出处 → 人工检查 → 发布 reviewed 版本。整个原目录不能直接递归加入问答索引，赛事指南、需求文档、开发提示词、凭证和原始日志都不默认进入领域知识库。

## 问答验收题的准备

| 类型 | 问题 | 所需证据或预期行为 |
|---|---|---|
| 有依据 1 | MCP Server 和一个 tool 有什么区别？ | 已审核定义与协议来源 |
| 有依据 2 | 工具检索与工具执行分别发生在何时？ | 工具发现/调用流程 |
| 有依据 3 | 单任务多步和用户多轮是不是一回事？ | 术语定义与示例 |
| 有依据 4 | 候选工具总量和每轮可见工具数怎样区分？ | N/A/K/U/C 定义 |
| 有依据 5 | 单步调用准确率能否代表多步任务成功率？ | 指标说明与适用条件 |
| 有依据 6 | 本次选定 benchmark 测的能力是什么？ | 选定版本的官方说明 |
| 有依据 7 | 该 benchmark 要求哪些模型与环境资源？ | 固定 commit 的 README 与实测接入记录 |
| 有依据 8 | 子集成绩为什么不能直接当作全榜成绩？ | 样本与评分范围说明 |
| 有依据 9 | 闭源模型怎样收到我们的资料片段？ | 已审核的 RAG 入门内容 |
| 有依据 10 | 知识库资料不足时系统应怎样回答？ | 已审核的证据与引用原则 |
| 无依据 1 | 团队未运行的某模型在本项目得了多少分？ | 明确没有本队实测，不编造成绩 |
| 无依据 2 | 未公开的某闭源模型具体训练集是什么？ | 说明资料未提供，不从模型常识猜测 |
| 无依据 3 | 知识库未覆盖的一个具体服务价格是多少？ | 说明未覆盖，不混入未经检索的外部信息 |
| 冲突 1 | 两份资料对工具规模的数字不同，哪个正确？ | 先按版本、候选范围与计量单位说明差异；无法确定则保留冲突 |
| 冲突 2 | 两份资料给出不同模型成绩，能否直接比较？ | 先核对任务集、方法、评分器与时间，不任取更高数字 |

两道冲突题在测试时使用明确标注的测试夹具或真实有版本差异的资料，不故意把虚构冲突发布成研究事实。10 道有依据题必须有标注的目标片段，才能单独检查检索与生成。

## 审核规则

来源是否原始、数字属于哪个版本、陈述是事实还是建议、内容是否可公开，四项分别核对。无法核对时保留待核验状态，不进入普通答疑索引。

团队报告不自动获得其中论文、数据和图表的再分发权。优先给原链接、自行摘要；运行数据只公开允许分享且已脱敏的部分。

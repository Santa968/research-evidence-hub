# 前端设计约束与参考

2026-11-02。当前只整理设计需求与参考，不编写页面。具体风格尚未选定，以下候选不代表最终选型。

## 已确定的要求

页面简洁、美观，优先通过布局、对齐、留白、字体和内容密度表达层次。导航、搜索、正文、引用、实验数据是主体。

- 不增加装饰性副标题、英文眉题、重复说明、口号和功能自夸。
- 不为每个区域重复安排“标题 + 二级标题 + 描述 + 卡片描述”。能由位置和控件表达的信息就不再写一句解释。
- 不默认加入巨幅 Hero、渐变文字、发光背景、玻璃卡片、悬浮装饰球、无意义数字统计和成排空泛功能卡。
- 不为每一段内容套卡片。列表用行、正文用排版、结果用表格、来源用紧邻内容的链接。
- 错误原因、操作反馈、引用、样本量、指标单位和必要字段名必须保留；简洁不能让用户猜当前状态。
- “不加二级说明”针对界面冗余文案。文章本身需要的章节标题、表格列名、输入标签和无障碍名称仍应准确存在。

“AI 味少”按以上可检查规则验收，不以某一种字体、配色或组件库代替判断。

## 已查看的 StyleKit 候选

参考：[Gallery Dark](https://www.stylekit.top/zh/styles/gallery-dark) 与 [实际 Showcase](https://www.stylekit.top/zh/styles/gallery-dark/showcase)。2026-11-02 已查看规则、组件说明及展示页。

它面向摄影与作品展示，适合借鉴暗色氛围和克制边界。应用于本项目时，需要重新处理正文、搜索、引用与结果表格的可读性，不能直接套用摄影首页。

| 参考点 | 本项目的处理建议 |
|---|---|
| 深色基底、有限强调色 | 可作为候选，最终颜色待团队选择 |
| 克制的边框与间距 | 可借鉴，用来组织正文和数据 |
| 全屏图片与巨大标题 | 本项目没有对应内容，不作为默认结构 |
| 极轻字体与很小的导航/元信息 | 中文长文和数值表需要更清晰的字号、字重与对比度 |
| 页面给出的长 Prompt | 只提炼经选择的规则，不整段照搬；本项目需求优先 |

该页内部也有需要人工判断的地方：规则限制衬线字，而所查看 Showcase 的主标题呈衬线造型；页面自评的部分次要文字配色未通过其 AA 检查。后续应以选定的视觉参考和实际可读性为准，不能把长 Prompt 当作无矛盾的设计规范。这里是对该候选的检查记录，不是对团队的选型决定。

## 有公开源码的设计参考

优先选择能查到维护者、代码与历史的真实网站。不能仅凭成品外观断言现代项目的每一行代码都由人工编写。若需要明确的早期人工设计样例，可优先查看 Distill 在 2016–2021 年发表的历史页面及对应版本。

| 参考 | 本项目可以借鉴什么 | 来源与边界 |
|---|---|---|
| [Docusaurus 文档页](https://docusaurus.io/docs) | 导航、目录、正文与搜索的位置关系；长文阅读宽度 | [Meta 开源项目](https://github.com/meta/docusaurus)，有公开贡献历史；[代码许可](https://github.com/meta/docusaurus/blob/main/LICENSE)为 MIT。只参考文档页结构，不照搬公告、表情和全部导航 |
| [Distill](https://distill.pub/about/) | 科研正文、图表、引用与阅读节奏；适合知识文章和实验分析 | 研究期刊运行于 2016–2021 年，目前暂停；[模板源码](https://github.com/distillpub/template)采用 [Apache-2.0](https://github.com/distillpub/template/blob/master/LICENSE)。作为排版参考，不引入旧框架与交互依赖 |
| [GitHub Primer Product UI](https://primer.style/) | 紧凑列表、筛选、表格与清晰状态；适合实验页 | GitHub 的设计系统；[React 源码](https://github.com/primer/react)与 [MIT 代码许可](https://github.com/primer/react/blob/main/LICENSE)可查。借鉴数据交互方式，不把界面做成 GitHub 克隆 |

这些站点的维护与许可信息已从第一方页面核对。这里只整理链接和自行总结，不复制其页面代码、品牌或素材；选用代码时另行记录具体版本与许可。

建议选择一个主视觉方向，再补充必要交互参考。不要把多个站点的字体、按钮、阴影和配色各取一套。

## 待团队选择的方向

| 方向 | 主要参考 | 更适合的内容 | 需要注意 |
|---|---|---|---|
| 文档与研究阅读 | Docusaurus 的结构 + Distill 的阅读节奏 | 长文、搜索、带引用问答 | 控制导航层级，不搬入复杂文档站全部功能 |
| 暗色编辑排版 | Gallery Dark 的氛围 + 内容型布局 | 深色展示、少量精选内容 | 用真实知识与表格验证，避免空旷大图占位 |
| 紧凑研究工作台 | Primer 的数据交互 | 高频筛选、实验对比、任务详情 | 保留阅读空间，避免堆统计卡与后台菜单 |

选型时使用同样的三份内容比较：一篇 800–1200 字中文知识正文、一条含 3 个引用的回答、一张含 10 行结果的表格。先比较“能否看清和找到信息”，再比较氛围。此处只规定比较方法，本轮不制作页面原型。

## 页面结构

全局仅保留项目名与“知识库 / 问答 / 实验”，当前导航项有清晰状态。未决定的主题切换、账号、通知等入口先不出现。

| 页面 | 主要布局 | 首屏必须看到 | 不增加的内容 |
|---|---|---|---|
| 知识库 | 搜索/筛选在前，条目列表或克制网格在后 | 搜索、分类、条目标题 | 先占一屏的宣传语、无数据的概览卡 |
| 知识正文 | 目录按需出现，正文为主，引用紧随相关内容 | 标题、正文开头、来源入口 | 在正文外重复写一段“关于本文”的说明 |
| 问答 | 问题与回答为主，来源在答案后或侧栏 | 输入框、最近一次问题与答案 | 机器人头像墙、能力口号、重复“AI 生成”装饰标签 |
| 实验列表 | 筛选 + 结果表，点击进入运行详情 | benchmark、配置、分子/分母、状态 | 凭空的“领先”“智能分析”或无来源总分 |
| 实验详情 | 运行信息与样本表，案例按需展开 | 配置与成绩，失败/环境错误可辨 | 默认展开全部配置 JSON、调试日志与实现细节 |

来源类型标识、缺失数据、错误状态是必要信息，保留且简短。配置原始 JSON、长日志放在“配置”或“日志”展开区域；用户作出判断需要的模型、任务集和评分方式在正文直接可见。

向 AI 提供参考时，还应附上“参考页哪个局部”的说明；仅给一个网址和“高级一点”不构成清晰的设计输入。桌面与手机分别检查布局，避免只在宽屏截图上成立。

## 设计验收

- 首屏能直接开始找资料、提问或看结果，不需要越过宣传区。
- 每段界面说明都回答实际问题；删除后不影响操作的重复文案被移除。
- 标题层级清晰，正文不会被大量细碎标签打断；不强制每块配副标题。
- 正文、引用与表格在浅/深色候选中均可读，不能把低对比度当作克制。
- 输入、焦点、加载、空结果和失败可辨，手机布局保持顺序与信息完整。
- 风格规则只保留团队选定的一套，源码或样式的引用来源可追溯。

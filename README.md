# 研知台 · Research Evidence Hub

面向 MCP 与 Agent 工具调用研究，把调研资料、带引用的 AI 答疑和可复现实验放在同一个网站。

从“这个 benchmark 在测什么”出发，读知识卡片、追溯原文，再查看团队运行的任务和失败案例。

## 本次交付

- 知识库：整理已有实训调研，支持分类、搜索、原文追溯。
- AI 答疑：根据已入库资料回答，显示引用，资料不足时说明限制。
- 实验展示：展示一个 benchmark 子集的真实运行结果、配置和案例。
- 可选：把运行日志做成可暂停、可逐步查看的工具调用回放。

当前为需求与方案整理阶段，平台开发按用户要求暂缓，尚未实现网站、完成评测或上线体验地址。已确定平台两人、benchmark 两人，具体账号分配由团队维护。项目名暂定。

## 开工

1. 阅读 [需求文档](docs/需求文档.md)，确认本次边界与验收标准。
2. 平台组评审 [前端设计约束与参考](docs/前端设计约束与参考.md)，风格尚未选定。
3. 按 [知识库与模型接入方案](docs/知识库与模型接入方案.md) 确认资料管理、模型 API 与引用链路；先区分工作台额度和开放平台 Access Secret。
4. benchmark 组按 [评测方案](docs/评测方案.md) 确定样本和实际运行；双方按 [技术与数据约定](docs/技术与数据约定.md) 交接数据。
5. 提交前逐项核对 [验收与提交](docs/验收与提交.md)。

[GitHub 任务索引](docs/GitHub任务索引.md) 与 [协作与排期](docs/协作与排期.md) 保留为后续实施拆分，当前不据此自行启动平台开发。

建议技术路线：Next.js + TypeScript 承载网站与服务端问答；Markdown / JSON 管理内容与结果；Python 独立运行 benchmark。依赖版本在正式开发时锁定。这里尚无应用代码和启动命令。

## 数据与复现

只把经过审核、允许公开的内容放入本仓库。既有实训原始文档暂留本地；来源和整理入口见 [资料清单](docs/资料清单.md)。

论文成绩、团队实测、预设演示分别展示。子集结果报告样本 ID、分母、版本、环境与评分方式；不直接宣称复现官方全榜。

密钥仅通过服务端环境变量配置，参照 [.env.example](.env.example)。已查到知乎开放平台直答与知识库 API 官方文档；账号调用、看山工作台额度是否支持独立 API，以及两者额度关系尚待验证。
